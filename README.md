# blink-editing — 《眨眼之间》剪辑方法论技能库

把沃尔特·默奇（Walter Murch）《眨眼之间：电影剪辑的奥秘（第2版）》拆成一套可被 AI 助手直接调用的 **Claude Agent Skill**。不是读后感，而是"结构而非摘要"：每条判断规则都可回溯到书中章节，可直接拿去审片、判断剪点、诊断节奏。

## 这是什么
- `SKILL.md`：技能入口。10 组核心框架 + 章节索引 + 主题索引，常驻预算很小。
- `chapters/ch01–ch19`：逐章笔记。每章含 核心思想／框架／概念／心智模型／反模式／实战示例／要点／关联。上篇 15 章逐章，下篇（数字剪辑）按主题合并为 ch16–ch19。
- `glossary.md`：52 条术语，按拼音排序，附章节引用。
- `patterns.md`：10 个可复用方法（何时用／怎么做／权衡）。
- `cheatsheet.md`：决策表——权重牺牲链、五问决策树、剪切频率对照、35 万英尺阈值、观众抱怨→病根定位。

## 怎么用
1. 把整个目录放到你的 skills 路径下（例如 `~/.claude/skills/blink-editing`）。
2. 不带参数调用 → 加载"核心框架"，作为审片/剪片时的判断依据。
3. 带主题（`六原则`、`眨眼`、`试映`、`以少胜多`、`随机存取`）→ 先读对应章节再回答。
4. 带章节号（`ch05`、`ch14`）→ 只加载该章。
5. 审片时给它一场戏的描述（素材、意图、当前剪法），它按六原则与分叉点逐条判断。

## 核心规则速览
- **六原则权重**：情感 51% ＞ 故事 23% ＞ 节奏 10% ＞ 视线 7% ＞ 二维平面 5% ＞ 三维连贯 4%；只能向下牺牲，前两项之和大于后四项之和。
- **剪接＝眨眼**：作为认真倾听者自然想眨眼的那一刻就是剪点，可以稍早一点点。
- **分叉点**：一场戏里"可以剪"的位置有限，绝不在两个分叉之间剪。
- **以少胜多**：用最少元素完成最多功能；细节超过临界点，观众从参与者变成评判者。
- **试映诊断**：观众只说哪儿疼，不说病根；集中抱怨某场戏时先查 5 分钟前是否缺说明。
